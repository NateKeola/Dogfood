# Tools, access and technical lift

**Decision:** start with authorized first-party exports, manual research and local diagnostics. Add a paid research provider only for a specific competitor/keyword evidence gap. Build an API integration only when repeated work justifies its credential, privacy and maintenance costs. No account, connection, subscription or key was created for this kit.

## Permission and data boundaries

A public-doc review needs no account connection. Client exports/property reads require authorized access; delegated read access is usually sufficient, not ownership transfer. Account verification, OAuth consent, new keys, paid usage, tracking configuration, submissions and publication are separate actions requiring the relevant user's/owner's authorization. Do none of them from a review prompt.

Before a future integration: select only required read endpoints/scopes; document property allowlist, storage/retention/deletion, recipient services, tenant isolation, secret storage and revocation. Keep bearer tokens out of URLs and all credentials out of logs/public reports; redact any API key a protocol requires in query parameters. Redact page/query values that expose personal data. Connectors can transmit inputs/results to another provider and may expose write tools: inspect their permissions and allow only the scoped reads. Preserve provenance, access errors, partial results, timestamps and unavailable values. Do not run vendor example code or trigger paid requests while estimating.

## Effort bands and acceptance

These are planning estimates for one small site, one locale, roughly 5–10 pages/2–3 templates, a working build, an experienced implementer and owner-supplied facts. **S = 1–4 hours, M = 0.5–2 working days, L = 3–5 working days, XL = discovery needed / over 5 days.** Use eight-hour working days. Bands overlap because estimates are uncertain. They exclude owner/access waiting, content collection, subscriptions, deployment and search-system response time. Re-estimate after inspection; rows are not additive quotes.

| Improvement | Class / band | Assumption and acceptance test | Limit / rollback |
| --- | --- | --- | --- |
| Crawler/index policy assessment | Configuration / S | Owner intent known; table maps each host/product to observed policy and intended behavior | Intent unknown → discovery. Any future change needs owner approval, directive tests and previous-config restore |
| Vertical/keyword/page plan | Content / M | One campaign; every proposed page has query evidence, unique value, verified facts and conversion | Manual analysis has no volume/difficulty claim; revise plan before publishing |
| Improve 3–5 priority pages | Content / M–L | Facts/assets supplied; owner verifies claims, intent and next action | Interviews/regulated review increase effort; version/restore copy |
| Render/navigation/metadata fixes | Code / M | Existing template architecture; direct-load content, links, statuses and canonicals pass sample | SPA/hosting rewrite → XL; revert tested commit |
| Truthful structured data | Code / S–M | Eligible facts exist; vocabulary, feature tests and visible-content parity pass | Missing private address is not solved by fabrication; remove/revert markup |
| Mobile/agent usability and performance | Code / M–L | Bounded bottlenecks; safe keyboard/mobile/DOM paths and agreed lab budgets pass | Architecture/third-party limits → XL; field result remains separate; revert regression |
| Manual visibility baseline | Configuration + content / S–M | Approved exports/query panel; denominators, dates and unavailable states retained | Sample is not universal visibility; repeat panel, no causal claim |
| One read-only reporting adapter | Integration / L | Existing approved credentials, one tenant/provider, stable endpoints; fixture reconciliation, denied-access and quota/backoff tests pass | Multi-tenant auth/security/storage → XL; disable adapter/revoke access via owner |
| Optional `llms.txt` pilot | Content + configuration / S | Named consumer; public links resolve, content matches pages, no sensitive data | N/A without consumer; no search uplift claim; remove file/config |
| `agents.txt` / WebMCP capability pilot | Integration / XL | Separate discovery proves consumer/version, useful task and safe confirmation boundaries | Experimental; not a default SEO deliverable or launch gate |
